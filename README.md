# ExoShadow Digital Twin

Веб-приложение для демонстрации цифрового двойника экзоскелета. Сервис принимает телеметрию приводов и датчиков, вычисляет сводную статистику, обнаруживает аномалии походки и перегрев, сохраняет отчёты и отображает результаты на интерактивной панели.

## Основные возможности

- REST API на FastAPI;
- валидация телеметрии через Pydantic;
- расширяемый движок анализа со стратегиями проверок;
- расчёт мощности, максимальной температуры и диапазона движения коленей через Pandas;
- обнаружение асимметрии коленей и перегрева приводов;
- демонстрационная панель с графиками, моделью ног и симулятором телеметрии;
- автоматическая документация OpenAPI;
- запуск локально или в Docker.

## Архитектура

```text
Браузер или внешний клиент
          │
          │ POST /analyze/summary
          ▼
       FastAPI
          │
          ├── Pydantic: проверка структуры данных
          ├── ShadowEngine: запуск стратегий анализа
          │     ├── GaitSymmetryStrategy
          │     └── ThermalSafetyStrategy
          ├── AnalyticsService: агрегированная статистика
          └── reports_history.json: история отчётов
```

## Требования

- Python 3.10 или новее;
- `pip`;
- современный браузер;
- интернет-соединение для загрузки Bootstrap и Chart.js с CDN на странице панели.

Зависимости Python перечислены в `requirements.txt`: FastAPI, Uvicorn, Pandas, NumPy и Pydantic.

## Локальный запуск

Команды необходимо выполнять из корня проекта: приложение использует относительные пути к `static/` и `reports_history.json`.

### Windows PowerShell

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m uvicorn app:app --reload --host 127.0.0.1 --port 8000
```

### Linux/macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m uvicorn app:app --reload --host 127.0.0.1 --port 8000
```

После запуска доступны:

- панель мониторинга: <http://127.0.0.1:8000/>;
- Swagger UI: <http://127.0.0.1:8000/docs>;
- схема OpenAPI: <http://127.0.0.1:8000/openapi.json>.

Также сервер можно запустить командой `python app.py`. В этом режиме автоматическая перезагрузка при изменении файлов отключена.

## Запуск в Docker

```bash
docker build -t exoshadow-digital-twin .
docker run --rm -p 8000:8000 exoshadow-digital-twin
```

Откройте <http://127.0.0.1:8000/>.

Файл истории создаётся внутри контейнера. При запуске с `--rm` он будет потерян вместе с контейнером, если не настроить постоянный том или внешнее хранилище.

## API

### `GET /`

Возвращает страницу `static/index.html`. Если файл отсутствует, сервер возвращает простую HTML-страницу с сообщением об ошибке.

### `POST /analyze/summary`

Принимает сессию телеметрии, анализирует все кадры и возвращает итоговый отчёт.

Пример запроса:

```json
{
  "session_id": "demo-001",
  "data": [
    {
      "timestamp": 0.0,
      "servos": [
        {"angle": 5.0, "current": 0.8, "temperature": 38.0, "load": 20.0},
        {"angle": 10.0, "current": 0.7, "temperature": 40.0, "load": 18.0},
        {"angle": 6.0, "current": 0.8, "temperature": 39.0, "load": 21.0},
        {"angle": 12.0, "current": 0.7, "temperature": 42.0, "load": 19.0}
      ],
      "heart_rate": 78,
      "accel_data": {"x": 0.1, "y": 1.0, "z": 0.0},
      "gyro_data": {"x": 0.0, "y": 0.0, "z": 0.0},
      "battery_voltage": 25.2
    }
  ]
}
```

Порядок приводов имеет значение:

| Индекс | Привод |
|---:|---|
| `0` | левое бедро (`L-Hip`) |
| `1` | левое колено (`L-Knee`) |
| `2` | правое бедро (`R-Hip`) |
| `3` | правое колено (`R-Knee`) |

Хотя модель разрешает список любой длины, текущая аналитика обращается к индексам `1` и `3`, поэтому каждый кадр должен содержать минимум четыре привода.

Пример ответа:

```json
{
  "session_id": "demo-001",
  "statistics": {
    "avg_power_watt": 75.6,
    "critical_temp": 42.0,
    "rom": {
      "l_knee": 0.0,
      "r_knee": 0.0
    }
  },
  "anomalies_found": 0,
  "anomalies": []
}
```

Некорректная структура запроса приводит к ответу `422`. Ошибка во время анализа возвращается как `400` с полем `detail`.

## Модель телеметрии

### Кадр `TelemetryFrame`

| Поле | Тип | Назначение |
|---|---|---|
| `timestamp` | `float` | временная метка или смещение сессии |
| `servos` | массив `ServoStatus` | состояние приводов; требуется минимум четыре элемента для текущих алгоритмов |
| `heart_rate` | `int` | пульс; сейчас сохраняется в модели, но не анализируется |
| `accel_data` | `Vector3` | вектор ускорения |
| `gyro_data` | `Vector3` | вектор угловой скорости |
| `battery_voltage` | `float` | напряжение батареи |

`ServoStatus` содержит `angle`, `current`, `temperature` и `load`. Вектор `Vector3` содержит координаты `x`, `y` и `z`.

## Аналитика

Для каждого запроса вычисляются:

- `avg_power_watt` — среднее значение `battery_voltage × сумма токов приводов` по кадрам;
- `critical_temp` — максимальная температура среди всех приводов и кадров;
- `rom.l_knee` — диапазон угла левого колена: `max − min`;
- `rom.r_knee` — диапазон угла правого колена: `max − min`.

Текущие стратегии обнаружения аномалий:

| Стратегия | Условие | Результат |
|---|---|---|
| Симметрия походки | разница между углами приводов `1` и `3` больше 50° | аномалия `Асимметрия`, уровень `2` |
| Температурная безопасность | температура любого привода выше 60°C | аномалия `Перегрев`, уровень `3` |

Пороговые значения сравниваются строго через `>`: ровно 50° и ровно 60°C аномалиями не считаются.

## Демонстрационная панель

Кнопка **START ENGINE TEST** запускает генератор тестовой телеметрии с интервалом 200 мс. Браузер хранит скользящее окно из 30 кадров и при каждом шаге отправляет всё окно в API.

Панель показывает:

- расчётную мощность и заряд батареи 6S;
- температуру и ток четырёх приводов;
- фазы `SWING`/`STANCE` для коленей;
- упрощённую SVG-модель ног;
- графики углов четырёх приводов;
- журнал обнаруженных аномалий.

## Хранение отчётов

Каждый вызов `POST /analyze/summary` дописывает одну строку в `reports_history.json`. Несмотря на расширение `.json`, файл имеет формат **JSON Lines / NDJSON**: каждая строка является отдельным JSON-объектом, а весь файл не является единым JSON-массивом.

На момент анализа в истории было 4306 записей и около 9 МБ данных. Демонстрационная панель выполняет до пяти запросов в секунду, поэтому файл растёт быстро.
